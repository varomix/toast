Toast guide

Toast lets you write the inside of a geometry node in Python syntax. The code runs once per point (or face, edge, corner, curve, instance), on every CPU core, compiled to native code: no Python runs while Blender evaluates the node tree.

Setting up

  1. Use the Blender build from the toast fork branch, and enable the Toast add-on (Preferences > Add-ons).
  2. Allow Auto Run Python Scripts (Preferences > Save & Load), or trust the file. Toast code in a .blend runs native code, so it follows the same rule as Python drivers.
  3. In a Geometry Nodes tree, add Toast > Toast. In the sidebar (N) > Node > Toast, press New to create a text with starter code, or pick one from Templates.

The node recompiles a moment after you stop typing: Blender's built-in compiler turns the code into native code in about 0.1 s, and reopening a file reuses the compiled code. Don't press Run Script in the Text Editor: Toast code isn't plain Python.

Editing

  • Follow Active Node (on by default, in the Toast panel and the add-on preferences): selecting a Toast node shows its code in the Text Editor of the same window. Turn it off to keep the Text Editor on whatever you are editing.
  • Templates: starter code for common jobs (noise, smoothing, scattering onto a surface, curves, instances...). In the node's Toast panel, a template is used by the node and sets its Run Over; in the Text Editor (Templates > Toast) it only creates the text.
  • Errors show on the node header, in the node's Toast panel and in the Text Editor's sidebar (N) > Toast, with Go to Error, which puts the cursor on the line (also inside a library).
  • Status: the Toast panels say whether the code is up to date, waiting for you to stop typing, or reused from an earlier compile.

Run Over sets what the code runs once for:

With Points, the code runs separately on each part that has points: the mesh, the point cloud and the curves. Input 0 is then the part being run on: point_count(0) and nearby_points(0, ...) see only its points.

Every element runs independently and in parallel. Writing @name changes the current element only; to change other elements, use set_point_attr() and the topology functions below, which are applied after the run in element order. The result never depends on the number of threads.

Language

Toast is a statically typed subset of Python.

  • Types: float, int, bool, vec2, vec3, vec4, quat (a rotation), mat4 (a transform) and lists. A variable's type is fixed by its first assignment; annotate to choose one: x: float = 1. Tuples of 2 to 4 numbers are vectors: (0, 0, 1).
  • Vectors: v.x, v.xy, v.zyx, v[0]; v.x = 1 sets one component. + - * / work between vectors of the same size and between a vector and a number.
  • Control flow: if/elif/else, while, for i in range(...), break, continue, x if cond else y, and/or/not, comparison chains like 0 < x < 1. return at the top level ends the current element.
  • Numbers: %, // and / follow Python (7 / 2 is 3.5). Integer division by zero gives 0 instead of crashing Blender.
  • Not supported: classes, dicts, growing lists, strings (except as names), recursion, *args, imports other than math and Toast libraries.

Lists

Lists have a fixed size, known when the code compiles (at most 4096 values):

Reading outside the list gives 0 and writing outside it does nothing, so a wrong index never crashes Blender. Lists are values, like vectors: b = a and passing a to a helper make a copy (unlike Python), so return a changed list from a helper. A list can't be stored in an attribute, and there is no append(). Where a vector is expected, a list of numbers is a vector: @position = [0, 0, 1].

Rotations and transforms

quat is a rotation and mat4 a 4x4 transform, the same as Blender's Rotation and Matrix sockets and attributes.

Any other name is your own attribute. Its type comes from an annotation, or from its first assigned value, or is float:

Writing an attribute that doesn't exist creates it on the Run Over domain.

With Run Over Instances, @position is the location of the instance's transform: writing it moves the instance. When the code writes both @transform and @position, the location comes from @position.

Parameters

param(name, default, min=, max=) adds a socket to the node; its type comes from the default. The same name always refers to the same socket.

Helpers and libraries

def helpers are compiled once for each combination of argument types they are called with:

Inside a helper, param(), math, noise, nearby_points() and the writing functions work; @ attributes and point_attr() don't (pass the values as arguments).

Put shared helpers in a library: a Text named toast_lib.<name> (or a file <name>.py in ~/.config/toast/lib or $TOAST_LIB_PATH) containing only defs and imports.

Editing a library recompiles every node that uses it.

Loops over related elements take a constant maximum count:

LoopVisits
for j in nearby_points(input, position, radius, max_count):Points within radius, closest first.
for p in face_points(input, face, max_count):The points of a face, in order.
for p in curve_points(input, curve, max_count):The points of a curve, from root to tip.
for f in point_faces(input, point, max_count):The faces using a point.
for q in point_neighbors(input, point, max_count):Points sharing an edge with a point.

Reading input 0 with these functions sees the geometry as it was before the run, even for attributes the code is writing.

These are applied after the run in element order: new elements are numbered by the element that created them, and when several elements write the same attribute, the highest index wins. On curves, points and curves can be removed but not added; removing the last point of a curve removes the curve.

Limits

  • Meshes, point clouds, curves and instances. Volumes and Grease Pencil are not supported.
  • Run Over Instances changes the instances of the top-level geometry only, like Blender's instance nodes; geometry inside instances runs with the other modes.
  • Linux and macOS (the node loads compiled code with dlopen).
  • No compiler needs to be installed on Linux: the fork has a built-in one. Elsewhere, or with the add-on's Compiler preference set to External, Toast uses g++ or clang++ (TOAST_CXX picks one).
